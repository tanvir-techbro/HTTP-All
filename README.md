# HTTP-All

One HTTP/1.1 server, five languages, one benchmark. C, C++, D, Rust, and TypeScript each
implement the same four endpoints using **only their standard library**, and get measured
the same way.

The point is not to find "the fastest language". The point is to hold the protocol
constant and see what the trade-offs actually look like: throughput, tail latency, memory,
CPU cost per request, and how much source code each one costs.

Two things make that comparison hold together:

- **Identical bytes on the wire.** A fixed header set with no `Date` and no `Server`, so
  `bytes/request` means the same thing everywhere.
- **Tiers.** Some runtimes ship an HTTP server (`node:http`) and some do not (`Rust`'s
  `std` gives you a socket). Each implementation declares its HTTP layer in `impl.env`, and
  results are grouped by it and **never ranked across it** — so you never see "Node's C++
  HTTP stack" beating "hand-rolled Rust" and mistake it for a language result. See
  [`SPEC.md` §1.1](SPEC.md).

## Quickstart

```sh
make doctor      # check the machine: wrk present? governor set? cores free?
make build       # build every implementation
make conform     # byte-exact protocol tests — nothing gets benchmarked until this passes
make bench       # run all scenarios against all implementations
make results     # regenerate results/latest/RESULTS.md
```

Requirements: a C compiler, `make`, `python3`, and `wrk` or `wrk2`. `make doctor` tells you
what is missing and how to install it.

## The contract in one screen

Four endpoints, exact bytes, standard library only. Full details in [`SPEC.md`](SPEC.md).

| Method | Path | Response |
|---|---|---|
| `GET` | `/` | `200`, `text/plain`, `Hello, World!\n` |
| `GET` | `/json` | `200`, `application/json`, `{"message":"Hello, World!"}` |
| `GET` | `/health` | `200`, `text/plain`, `OK` |
| `POST` | `/echo` | `200`, `application/octet-stream`, the request body back |

Plus `404`/`405`/`400`/`411`/`413`/`431` for the error cases, HTTP/1.1 keep-alive, and a
fixed header set with **no `Date` and no `Server`** — so the bytes on the wire are identical
across languages and `bytes/request` means something.

Configuration is `PORT` (default 8080) and `HOST` (default 127.0.0.1). Servers announce
themselves on stdout with `LISTENING <host>:<port>` once the socket is accepting.

## Layout

```
SPEC.md              the normative contract: endpoints, bytes, build/run interface
CONTRIBUTING.md      how to add a language, and the review checklist
docs/methodology.md  machine state, pinning, scenarios, metrics, threats to validity

harness/
  doctor.sh          environment preflight (generator, governor, cores, toolchains)
  conformance.py     byte-exact protocol tests, raw sockets
  bench.sh           build + run + measure, writes results/<run-id>/
  report.py          raw output -> summary.csv + RESULTS.md
  scenarios.tsv      the benchmark scenarios
  lua/echo.lua       POST body for the echo scenario
  lib.sh             shared shell helpers

C/ CPP/ D/ Rust/ TS/   empty, awaiting implementations
results/             generated; raw output kept so any number can be re-derived
```

An implementation directory is `build.sh` + `run.sh` + `impl.env` + `README.md`. `impl.env`
declares which tier the numbers belong to:

```
HTTP_LAYER=hand-rolled      # hand-rolled | runtime
RUNTIME=node 26.10.0
```

## Adding an implementation

See [`CONTRIBUTING.md`](CONTRIBUTING.md). Short version: create a directory with
`build.sh`, `run.sh`, and `README.md`, satisfy `SPEC.md`, pass `make conform`, and open a
PR that includes the `results/<run-id>/` output for the machine it was measured on.
